# Yandex Direct Bidder

Консольный биддер для Яндекс.Директа. Управляет ставками по вашим правилам, помогает не платить больше, чем нужно.

Основная стратегия — **адаптивный скальпинг**: начинает с минимальной ставки и постепенно поднимает её шагами, которые растут, пока не выиграет аукцион (пока ставка не достигнет цены входа в спецразмещение). Когда победа достигнута — ставка замораживается, и биддер следит, чтобы её не перебили.

## Что умеет

- **Адаптивный скальпинг ставок.** Начинает с минимума, поднимает шаг за шагом, пока ставка не достигнет цены входа в спецразмещение.
- **Работа по правилам из YAML.** Другая стратегия — обычные правила: «entry + 5», «фикс 100», «не выше 150» и т.д.
- **Безопасный режим.** `dry_run` — считает, но не отправляет ставки. `sandbox` — работает с тестовым API Яндекса.
- **Хранение состояния.** Помнит, на каком шаге скальпинга каждая фраза.
- **Логи с ротацией.** Всё пишется в файл и stderr.
- **Уведомления в Telegram.** При ошибках и по итогам запуска.
- **CLI.** Команды `--status` и `--reset`.
- **Fail-fast.** Пустой токен или битый YAML останавливают запуск до отправки запросов к API.

## Как это работает

Схема одного запуска:

```
1. Читаем .env (токен) и config.yaml (настройки и правила).
2. Проверяем конфиг: токен, файл правил.
3. Просим у Яндекса цену входа в спецразмещение по каждой фразе.
4. Для каждой фразы:
     - если current < entry → поднимаем ставку на адаптивный шаг (не выше entry);
     - если current ≥ entry → уже выигрываем, не трогаем.
5. Отправляем изменения пакетом (или только логируем при dry_run).
6. Пишем лог, шлём уведомление, обновляем state.json.
```

Схема скальпинга на временной шкале (запуски раз в 30 минут, entry = 100 ₽):

```
запуск 1:  30 ₽   (start_bid)
запуск 2:  35 ₽   (+5)
запуск 3:  45 ₽   (+10)
запуск 4:  60 ₽   (+15)
запуск 5:  80 ₽   (+20)
запуск 6: 100 ₽   (+25 → cap по entry)
запуск 7: 100 ₽   уже выигрываем, заморожено
```

Итого 6 шагов, 3 часа.

```bash

```

Откройте `.env` и вставьте токен (см. ниже).

## Настройка

### `.env` — секреты

В `.env` живут **только секреты**. Всё остальное — в `config.yaml`.

```dotenv
YANDEX_DIRECT_TOKEN=ваш_токен_сюда
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

**Как получить токен:**

1. Зайдите на https://oauth.yandex.ru/ и создайте приложение типа «Для доступа к API или отладки».
2. В правах приложения отметьте «Яндекс Директ».
3. Получите OAuth-токен.
4. Подайте заявку на доступ к API в кабинете Директа (обычно одобряется быстро для личного использования).
5. Для работы с песочницей получите **отдельный** токен песочницы.

**Telegram (опционально):**

1. Создайте бота у `@BotFather`, получите `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение.
3. Узнайте свой `TELEGRAM_CHAT_ID` у `@userinfobot` или через `getUpdates`.
4. Впишите оба значения в `.env`. Оставьте пустыми, если уведомления не нужны.

### `config.yaml` — конфигурация

Все настройки, лимиты и правила живут в `config.yaml`. Этот файл **можно и нужно коммитить** в git.

```yaml
# Режим работы
mode:
  sandbox: true      # true → api-sandbox, false → боевой API
  dry_run: true      # true → считает, но не отправляет ставки

# Кампания
campaign:
  id: 12345678       # ID вашей кампании
  client_login: null # заполните для агентских аккаунтов

# Параметры API
api:
  timeout: 30
  retry_count: 3
  max_concurrent: 5
  max_keywords_per_batch: 50

# Логи
logging:
  file: logs/bidder.log
  level: INFO

# Файл состояния
state:
  file: state.json

# Лимиты (работают во всех режимах)
limits:
  max_bid: 150       # никогда не выше
  min_bid: 30        # и не ниже
  no_downgrade: true # понижать ставки запрещено

# Стратегия: 'scalping' или 'rules'
strategy: scalping

# Настройки скальпинга
scalping:
  start_bid: 30      # с чего начинаем
  base_step: 5       # первый шаг
  step_increment: 5  # рост шага за каждый следующий шаг
  max_step: 50       # потолок шага

# Правила (используются только при strategy: rules)
rules:
  defaults:
    bid: 100
  rules:
    - name: "Совсем дешёвые — держим фикс"
      when:
        premium_entry_price:
          lt: 50
      then:
        type: fixed
        value: 50
```

**Четыре шага безопасной настройки:**

1. **`sandbox: true, dry_run: true`** — отладка. Запустите и убедитесь, что всё читается и считает.
2. **`sandbox: true, dry_run: false`** — песочница. Ставки реально меняются, но не тратят деньги.
3. **`sandbox: false, dry_run: true`** — смотрим, что биддер сделал бы на боевой кампании, ничего не меняя.
4. **`sandbox: false, dry_run: false`** — рабочий режим.

## Использование

### Обычный запуск

```bash
python bidder.py
# или
uv run bidder.py
```

**Что произойдёт:**

- Если `strategy: scalping` и `dry_run: true` — посчитает и покажет изменения, но не отправит.
- Если `dry_run: false` — отправит новые ставки в Яндекс.
- Exit code:
  - `0` — успех;
  - `1` — ошибка API;
  - `2` — ошибка конфигурации;
  - `3` — ошибка в правилах.

### Просмотр статуса

```bash
python bidder.py --status
```

Покажет таблицу:

```
KeywordId    | current | entry | step_n | фаза
-------------------------------------------------
      111    |    45   |   80  |   2    | скальпинг
      112    |   100   |   90  |   0    | выигрываем
      113    |    30   |   —   |   0    | —
```

- `current` — текущая ставка
- `entry` — цена входа в спецразмещение
- `step_n` — на каком шаге скальпинга фраза
- `фаза` — `скальпинг` / `выигрываем` / `—`

### Сброс ставок

```bash
python bidder.py --reset
```

- Выставит все ставки в `scalping.start_bid` (например, 30 ₽).
- Обнулит `state.json`.
- Скальпинг начнётся заново.

**Важно:** `--reset` уважает `dry_run`. Если `dry_run: true`, ставки **не сбросятся** — только покажет, что бы сбросил. Чтобы реально сбросить, поставьте `dry_run: false`.

## Стратегия scalping подробнее

**Идея:** не переплачивать. Минимальная ставка, которая побеждает в аукционе — это и есть справедливая цена. Скальпинг её находит.

**Правила одного шага:**

| Ситуация | Что делает |
|---|---|
| `entry` неизвестна | пропускает |
| `current` нет | ставит `start_bid` |
| `current ≥ entry` | ничего, уже выигрываем |
| `current ≥ max_bid`, а `entry > max_bid` | стоит, цена недостижима |
| `current < entry` | `new = current + step(n)`, где `step(n) = base_step + n × step_increment`, с потолком `max_step`; `new` не выше `entry` и не выше `max_bid` |

**Адаптивный шаг** растёт с каждым пройденным шагом — чем дольше ищем, тем смелее двигаемся. Это экономит запуски.

**Тюнинг:**

- Хочется быстрее — увеличьте `base_step` или `step_increment`.
- Хочется аккуратнее — уменьшите `step_increment` и `max_step`.
- Хочется дешевле остановиться — уменьшите `max_bid`.

Параметры меняются **без правки кода**, только в `config.yaml`.

## Автоматизация по расписанию

### Linux / macOS (cron)

Откройте crontab:

```bash
crontab -e
```

Добавьте строку — запуск раз в 30 минут:

```cron
*/30 * * * * cd /home/user/rich_bidder && /home/user/rich_bidder/.venv/bin/python bidder.py >> logs/cron.log 2>&1
```

### Windows (Task Scheduler)

1. Откройте «Планировщик задач» → «Создать задачу».
2. **Триггер:** повторять каждые 30 минут, бесконечно.
3. **Действие:**
   - Программа: `C:\projects\py\rich_bidder\.venv\Scripts\python.exe`
   - Аргументы: `bidder.py`
   - Рабочая папка: `C:\projects\py\rich_bidder`

### systemd (Linux, продакшн)

Создайте `/etc/systemd/system/rich-bidder.service`:

```ini
[Unit]
Description=Yandex Direct Bidder
After=network-online.target

[Service]
Type=oneshot
WorkingDirectory=/home/user/rich_bidder
ExecStart=/home/user/rich_bidder/.venv/bin/python bidder.py
User=user

[Install]
WantedBy=multi-user.target
```

И таймер `/etc/systemd/system/rich-bidder.timer`:

```ini
[Unit]
Description=Run bidder every 30 minutes

[Timer]
OnBootSec=5min
OnUnitActiveSec=30min
Unit=rich-bidder.service

[Install]
WantedBy=timers.target
```

Включите:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now rich-bidder.timer
```

Пишутся в `logs/bidder.log`. Ротация: 10 МБ, хранятся 14 дней, старые архивируются.

Дополнительно всё дублируется в stderr. Пример:

```

2026-09-16 21:07:37 | INFO | Получено ставок: 42. Units: {'Units': 15, 'Units-Rest': 985}
2026-09-16 21:07:37 | INFO | KW 111: 30 → 35 (шаг #0: current=30 + step=5 → 35)
2026-09-16 21:07:37 | WARNING | DRY-RUN: пропускаю отправку 3 изменений
```

### Telegram

Если в `.env` заполнены `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`:

- 🧪 **DRY-RUN** — сводка изменений при отладке;
- ✅ **Применено** — сводка реальных изменений;
- ⚠️ **Bids.set** — частичные ошибки;
- ❌ **Ошибка авторизации / API / упал** — критические ошибки.

Оставьте поля пустыми, если уведомления не нужны.

## Безопасность

**Что защищает ваш бюджет:**

- **`limits.max_bid`** — жёсткий потолок ставки. Никакая формула не пробьёт его.
- **`limits.no_downgrade: true`** — ставка никогда не понижается автоматически.
- **`limits.min_bid`** — защита от нуля и случайных опечаток.
- **`dry_run`** — безопасный режим без реальных изменений.
- **`sandbox`** — тестовый API, деньги не тратятся.
- **`--reset` уважает `dry_run`** — нельзя случайно сбросить боевые ставки, думая, что это тест.

**Что защищает доступ:**

- **Токен не пишется в логи и трейсбеки.** Все поля с секретами помечены `repr=False`.
- **`.env` в `.gitignore`.** Токен не попадёт в git-коммит.
- **Fail-fast на заглушку.** Если в `.env` осталось `your_oauth_token_here` — приложение упадёт с понятной ошибкой до отправки запросов к API.

## Решение проблем

### `DirectApiError: [53] Ошибка авторизации Недействительный OAuth-токен`

**Причины:**
- В `.env` всё ещё шаблон `your_oauth_token_here`.
- Токен просрочен.
- Токен не даёт прав на Яндекс.Директ.
- Токен от боевого кабинета, а `mode.sandbox: true` (или наоборот).

**Решение:** смотрите подсказку в логе — там код и что делать. Если код `58` — песочница vs. боевой режим.

### `[53]` в первый же запуск

Проверьте, что токен действительно вписан:

```bash
python -c "import os; from dotenv import load_dotenv; load_dotenv(); print(os.getenv('YANDEX_DIRECT_TOKEN')[:10])"
```

Должно напечатать начало токена, а не `your_oaut`.

### `CampaignIds` возвращает 0 ставок

- В кампании нет активных фраз.
- Кампания в архиве.
- `campaign.id` указан неверно.

Проверьте `--status` — если пусто, дело в кампании.

### `premium_entry_price` пустое для всех фраз

- У кампании нет показов за последнее время — Яндекс не отдаёт цены входа.
- Фраза не участвует в аукционе.
- Токен без нужных прав.

Скальпинг в этом случае ничего не сделает. Запустите утром или после первых показов.

### `no_downgrade` мешает изменениям

Если вы вручную подняли ставку выше `max_bid` и хотите её понизить — временно установите `limits.no_downgrade: false`, один раз запустите, потом верните `true`.

### Ошибки баллов API (`Units-Rest = 0`)

Слишком частые запуски или много фраз. Уменьшите частоту расписания или ограничьте число фраз (по кампаниям, по группам).

### Rate limit (`5 одновременных запросов`)

Уже встроено: семафор на 5 запросов. Если увидели — уменьшите `api.max_concurrent` до 3.

## FAQ

### Биддер тратит реальные деньги?

- При `dry_run: true` — **нет**, только считает.
- При `sandbox: true` — **нет**, тестовый API.
- При `dry_run: false, sandbox: false` — **да**, ставки реально меняются в боевом кабинете.

### Он может выставить больше, чем я готов платить?

Нет. `limits.max_bid` — жёсткий потолок. Действует и в scalping, и в rules.

### Может понизить ставку случайно?

Нет. `limits.no_downgrade: true` запрещает. Понижение возможно только вручную или через `--reset`.

### Нужен ли ML / Q-learning?

Нет. Ваша задача — «не переплачивать» — решается детерминированным скальпингом. ML и Q-learning требуют миллионов взаимодействий и данных, которых у отдельной кампании нет.

### Как перейти с одной стратегии на другую?

Измените в `config.yaml` строку `strategy: scalping` на `strategy: rules` (или наоборот). Всё.

### Как добавить новое правило?

В `config.yaml`, секция `rules.rules[]`. Доступные типы действий: `fixed`, `entry_plus`, `entry_minus`, `entry_multiply`, `current_plus`. Операторы: `lt`, `lte`, `gt`, `gte`, `eq`, `ne`, `between`, `is_null`, `not_null`.

### Как поменять токен?

Отредактируйте `.env`. Единственный файл, где живут секреты.

### Как поменять ID кампании?

Отредактируйте `config.yaml`, секцию `campaign.id`.

### Где хранится состояние?

В `state.json` рядом с `bidder.py`. Не коммитится (в `.gitignore`). Можно удалить — скальпинг начнётся заново с `start_bid`.

### Как узнать, что делает биддер прямо сейчас?

```bash
python bidder.py --status
```

Покажет текущие ставки, цены входа и шаг скальпинга по каждой фразе.

### Что если Яндекс.Директ упал?

Ретраи `tenacity` — 3 попытки с экспоненциальной задержкой. Если совсем недоступен — вернёт exit code 1, пришлёт Telegram-уведомление. Следующий запуск по расписанию попробует снова.
